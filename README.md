# 项目上线前检查助手

面向修船项目实施工程师的上线前检查台账：把船次、专业、施工队、流程节点、结算口径和验收证据逐项核实，再交业务负责人评审。

纯静态单页应用，无后端、无外部依赖，可离线运行。

## 功能

- **项目文件夹**：首页新建、搜索和打开独立的上线项目；每次重新打开或刷新都回到项目列表，主动选择后才显示该项目记录。
- **空白新项目**：默认没有历史记录或示例数据；可在创建时主动选择修船模板，也可进入项目后追加。
- **项目隔离**：检查项、上线范围和已写入的核对结果按项目保存；切换或退出项目时清空临时粘贴明细、筛选、编辑、撤销及待处理的导入，避免串入其他项目。
- **五类检查清单**：业务规则确认、关键测试、数据核对、问题闭环、上线准备，支持新增 / 修改 / 删除。
- **修船模板**：公司结算、车间分配与月度结算、工程签单、物资领采，4 类共 32 项。追加时按模板键去重，全部从待处理开始；模板是核对提示，具体规则须现场确认。
- **上线范围**：记录项目 / 工程编号、拟上线版本、取数截止时点及核查范围，随备份和报告保留。
- **阻断判定**：所有类别的关键项均参与判定；规则须有确认人和有效依据，关键项须留验收证据，核心测试须有实际结果。严重缺陷须完成复测、历史错数处理和关联影响评估。
- **完成进度**：按「有效通过 /（总数 − 有理由的不适用）」计算。标了通过但缺闭环或证据仍未完成；空台账、全不适用不显示 100%，完成后提示人工评审。
- **修船明细核对**：源系统与系统内分别选列，可组合单据 / 流程号、船次 / 工程编号、专业、期间、施工队、明细行号，支持不同列顺序、带引号的 CSV 和 Excel TSV。
- **明细差异与质量**：同时核对行数、正负合计和每行数值分布，避免净额相等掩盖抵消；区分真实 0、空值、非法数、缺单号和已选维度缺值。同一组合键多行只提示核实，不能直接认定重复业务。
- **核对结果写入**：保存实际维度范围与统计，保留原备注，状态改为进行中；输入、映射或精度变化时旧结果立即失效。单份数据仅做统计，不代表双向一致。
- **筛选**：按类别、负责人、状态、关键词及「只看未完成」组合过滤。
- **数据本地保存**：各项目自动保存在当前浏览器；旧版台账保留为“历史项目”，原记录也保留。兼容旧 JSON 备份，导入时始终新建项目，不覆盖任何现有项目。
- **按项目导出**：备份与可打印 HTML 报告只包含当前项目，文件名带项目名称，可打印或另存为 PDF。

## 使用

1. 双击 `index.html`，或在仓库 Pages 地址打开。
2. 在“项目文件夹”首页点“新建项目文件夹”，填写项目名称，可选填工程 / 船次编号、拟上线版本；默认创建空白台账，也可主动选模板。
3. 选择“打开项目”继续已有工作。升级前台账会保留在“历史项目”中，不会自动打开或带进新项目。
4. 填写本项目取数时点与核查范围，再按已确认规则填写负责人、实际结果和证据。不适用项须写明理由，不把培训说明或模板当作验收通过。
5. 明细核对前统一船次、期间、流程状态、单位及金额口径；核实两侧列映射与所选维度。默认2位小数，可选3 / 4 / 6位，按十进制对称四舍五入核对。切换项目后临时粘贴内容会清空，已写入的核对记录保留在原项目。
6. 每天收工前点“备份本项目”导出 JSON。导入备份会新建独立文件夹，同名项目自动加序号，已有项目保留。
7. 上线评审时导出报告，报告包含当前项目名称、上线范围、每项证据、有效通过数及阻断原因，交业务负责人签字确认。点“项目文件夹”返回首页；刷新或重新打开应用也会回到首页。

> 文件夹是应用内的项目分类，不是电脑硬盘目录。数据仅保存在当前浏览器，不会上传或跨电脑同步；换电脑或清理浏览器前，请分别备份要保留的项目。

## 目录结构

```
index.html                      页面结构与文案
assets/styles.css               样式
assets/app.js                   业务逻辑（清单、筛选、自动核对、报告）
assets/shiprepair-templates.js  修船场景的待核对模板
assets/reconcile.js             CSV/TSV、组合键和十进制核对核心
assets/readiness.js             阻断、有效完成率与评审状态
assets/projects.js              项目隔离、历史台账迁移与独立导入
tests/                         业务边界与集成回归（Node 内置测试）
.github/workflows/pages.yml     GitHub Pages 自动部署
```

## 部署到 GitHub Pages

**每次版本提交前，先汇总改动、验证结果、限制和拟提交范围，取得用户对当次版本的明确确认。** 确认前只在本地修改与验证，不执行提交、推送、PR、合并、打标签或发布。详见 [AGENTS.md](AGENTS.md)。

获准推送到 `main` 分支后，Actions 会先运行测试，再发布静态页面与 assets。
首次使用需在仓库 **Settings → Pages → Source** 中选择 **GitHub Actions**。

## 验证与限制

需要 Node.js 20 或更新版本，仅测试时需要 Node，应用运行不需要安装依赖：

```bash
node --test tests/readiness.test.js tests/reconcile.test.js tests/projects.test.js tests/app.test.js
```

核对只针对粘贴的明细及已选维度；不会连接 CRS、读取数据库或验证导出范围是否完整。金额字段、单位换算、跨流程汇总边界和显示节点须由项目现场确认。单份统计或零差异不能替代业务验收。

数值输入若转换会损失十进制有效值，或合计超出安全数值 / 可表示精度范围，会标为非法或停止核对；请拆分范围或采用经验证的精确账务工具。数据仍仅保存在本浏览器，关键操作前请备份。

同一项目在多个窗口同时编辑时仍按最后一次保存为准；不同项目的保存会保留其他项目的最新记录。存储不可用或损坏时会显示错误并保留原记录，不会清空后重新生成示例。
