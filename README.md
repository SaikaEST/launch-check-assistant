# 项目上线前检查助手

面向实施工程师的上线前检查台账：把业务口径、关键测试、数据核对、问题闭环和上线准备逐项确认清楚，再决定是否具备上线条件。

纯静态单页应用，无后端、无外部依赖，可离线运行。

## 功能

- **五类检查清单**：业务规则确认、关键测试、数据核对、问题闭环、上线准备，支持新增 / 修改 / 删除。
- **阻断判定**：关键规则未确认、核心测试未通过、严重缺陷未关闭时，首页提示「暂不具备上线条件」并列出具体项目。
- **完成进度**：按「通过 /（总数 − 不适用）」计算，实时统计未完成项、严重问题与阻断项。
- **明细自动核对**：粘贴源系统与系统内两份明细，按单据号比对漏抓、多抓、重复单号、数量差异，并计算正数合计、负数合计、零值行数与空值行数。
- **筛选**：按类别、负责人、状态、关键词及「只看未完成」组合过滤。
- **数据本地保存**：自动写入浏览器 localStorage；支持 JSON 备份与导入。
- **报告导出**：生成可打印的自包含 HTML 报告，可直接打印或另存为 PDF。

## 使用

1. 双击 `index.html`，或在仓库 Pages 地址打开。
2. 根据示例数据了解字段结构，点「清除示例数据」后录入真实检查项。
3. 每天收工前点「备份」导出 JSON；换电脑或清理浏览器前务必先备份。
4. 上线评审时点「导出报告」，交业务负责人签字确认。

> 数据仅保存在当前浏览器，不会上传到服务器。

## 目录结构

```
index.html                      页面结构与文案
assets/styles.css               样式
assets/app.js                   业务逻辑（清单、筛选、自动核对、报告）
.github/workflows/pages.yml     GitHub Pages 自动部署
```

## 本地预览

```bash
python -m http.server 8080
# 打开 http://localhost:8080
```

## 部署到 GitHub Pages

推送到 `main` 分支后，Actions 会自动构建并发布。
首次使用需在仓库 **Settings → Pages → Source** 中选择 **GitHub Actions**。
